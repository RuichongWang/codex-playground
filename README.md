## `done` —— 一个发 `done` 的最小硬核

**给一件干完的活发一个「它自己伪造不了的 `done`」,依据是开卡时就冻住的 accept criteria,
并把这件事记成一行改不掉的账。**

设计:[`docs/DESIGN.md`](docs/DESIGN.md)(10 分钟读完)· 零依赖,Python 3 标准库

## 五分钟跑通第一张卡

用 `cards/demo.json` —— **教程专用的演示卡**,只有两条验收条件(一条命令答、一条人答),
配套的两份示例报告仓里现成带着。**下面每一行都可以直接贴进终端,从头到尾跑得通。**

```bash
make check                                   # 七条规矩各跑一次会报错的例子 + 正常通过的例子
H=$(python3 -m done.cli head)                # 账的头,第一次是 64 个 0

python3 -m done.cli open cards/demo.json --chain-head "$H" --by 你的名字
# 干真活的时候,开卡前先查一次记忆库(这类活别处踩过什么坑),把结果带上:
#   --查库 reports/<查库记录>.json
#   承重的是哪两个栏名,跑 `python3 tools/lookupcols.py` 看 —— 这儿不抄一份,抄一份必漂。
#   **那两个里必须有一个**:一个填「你查了,查的是啥」,一个填「你明说这次没查」。
#   数数的工具(tools/lookupstat.py)按这两栏分类,栏名写岔一个字它两边都归不进去,
#   而「栏名写岔了」和「这一栏根本没记」在那张表上同形。别的栏随便写,那是给人看的备注。
#   说了查过的那一条,必须跟着记「用上了」,一次都没用上也要写:{"用上了": "没有,都不对路"}。
# 不传就记「没查」。**查了什么都没查到也要记** —— 空手而归和根本没查,不记下来在账上同形。

H=$(python3 -m done.cli head)
python3 -m done.cli judge cards/demo.json --chain-head "$H" --at HEAD --report reports/demo-judge.json

H=$(python3 -m done.cli head)
python3 -m done.cli reflect cards/demo.json --chain-head "$H" --note reports/demo-reflect.json

python3 -m done.cli log
python3 -m done.cli verify
```

**那两份示例报告是教程用的样本** —— 真干活的时候,每一份都得由真的判官写。
一张真卡要交几份、各由谁答,**这儿不写** —— 先 `open` 那张卡,再不带 `--report` 跑一次
`judge`,它会一次把缺的全列出来、每份该由谁答。(这儿原来举例说「要好几个人分别答好几条」,
而盘上那张真卡其实是一个人答三条 —— 照它下一句自己教的办法跑一遍就打脸了。)
(**得先开卡**:没开过的卡直接判会被拒,这是设计如此 —— 判据必须在干活之前就锁住。)

**开卡这一步会先给判据做一次体检。** 开卡之后再改判据要留疤,而且这张卡之前的判决
全部作废,所以能在开卡那一刻看出来的就在那儿拦住:

- 带「找出」两个字的,「过」只能是「没找到」;以「吗?」收尾的,只能是「是」或「否」
  (判决那一步的答域是照「过」定的 —— 写反了,意思整个反过来)。
  **两条都撞上的时候「找出」赢** —— 「找出一处循环依赖吗?」按找反例算
- 两种都不是 → 拒(答域不明,判的人不知道该答什么)
- 判者叫「改动审阅人 / 说明书审阅人 / 库审阅人 / 代码审阅人」的,「凭什么答」里得真给他那样东西
- 开工前查库那一栏,**承重的那两个栏名至少得有一个**(哪两个跑
  `python3 tools/lookupcols.py` 看;两条:承重的栏在不在 ·
  说了查过的有没有跟着记「用上了」)

**这道门的闸是「它有没有逮错过」,不是「它逮着过东西没有」。**
中间试过后者:`tools/openreplay.py` 重放全部历史数每条检查命中几次,命中 0 次的不许留 ——
当场按这条删掉了上面第一行那两条。下一个审阅人把那个数拆开看,发现命中最多那条的
13 次里 11 次是凑数(打在这套栏目存在之前的老格式上)、2 次是**真逮错了**,
其中一处在判据包里活着:一句标准是非问,只因为问号后面跟了括号补语就被判答域不明,
**而那个括号正是上一次修复专门补的 —— 它拦的是修复,含糊的版本反而过得去**。
「从没逮着过」只说明这类坏法还没发生过,而入口检查本来就是为还没发生的事设的。
所以闸换成:**对现在盘上的每一张卡、每一个判据包、说明书里的每一条范例都要放行,
一处误伤就红**。那个历史读数留着,只印不拦。

还会把每条命令判据**当场跑一遍**(在一个临时副本里,不在你的工作目录里),
把它开卡时是什么颜色记进账里(`开卡实况`)—— 这一条**记,不拦**:
一条一开卡就绿、判决时也绿的判据,和一条不存在的判据是一样的,
而这件事机械拦不住(体检卡就该一开卡全绿),只能靠两头都有读数才看得见。

```bash
python3 tools/opencheck.py --self     # 盘上每条判据全放行(闸)· 坏样卡全拦下
python3 tools/openwired.py            # 拿一张写坏的卡走真的开卡命令,看它是不是真被拒
python3 tools/openreplay.py           # 名册上每条检查在历史里逮着过几次(0 次的也印)
```

`--chain-head` 每次都要传:**写入之前你必须先看过账的头。**
它挡的是**静默**篡改,不是有决心的对手 —— 这一点没有夸大。

## 一条判据长什么样

**每一条判据 = 一个只能从三个值里挑一个来答的问题,带着「凭什么答」和「哪边算过」。
唯一的区别是谁来答:一条命令,还是一个读者。**
哪三个值不是固定的,由这一条的「过」定 —— `python3 tools/answerdomain.py` 印出来。

```json
{"id":"a1","问":"make check 退出码是 0 吗?","过":"是",
 "判者":{"cmd":"make check","答是":"exit0"},"凭什么答":"命令的退出码与输出"}

{"id":"x1","问":"找出这次改动里一处行为变了而说明书没跟着改的地方","过":"没找到",
 "判者":{"读者":"改动审阅人"},
 "凭什么答":"这次改动的原文,以及说明书对应的那几段;答「没找到」就写清你逐条核了哪几句"}
```

- **`答不了` 是一等公民。** 不算过,而且**直接指向这条判据要重写** —— 逼判官在没证据时硬答,是最大的漏水口。
- **「有没有…」这类问题,一律写成「找出一个…」。** 答域换成 `找到` / `没找到` / `答不了`,通过的那一边是 `没找到`。
  理由:答「有」只要举一个反例,答「没有」要穷举整份文件 —— 而报告只装得下一段引文,于是「没有」成了免费答案(实测被这么蒙混过一次)。
  **答「没找到」必须写清 `搜了什么`**,而且账上会记一句:**没找到 ≠ 没有,只是这一轮没逮着。**
- **判者是人的时候要写明「哪一个人」**(冷读者?改动审阅人?)。不写明就会问出一个他结构上答不了的问题 —— 实测过:只许看说明书的人,对着「看这次改动」那条只能答「答不了」。
- **读者那一档要交一份报告**,每条 `{答, 引文, 证据}`,而 **`引文` 必须是 `证据` 的逐字子串**。
  **`证据` 允许是几段拼起来的**,但每一段必须逐字、并标明出处 —— 要证明「说明书里这句现在是假的」,
  那句话和打脸它的输出天生隔着几百行,强求一段连续原文等于逼诚实的判官交不出证据。
  于是「判官照没照判据答」是机械可查的;人只剩一件事要抽查:**这条判据是不是在要求判官形成看法,而不是找到证据。**
- **一张卡至少一条由命令来答。** 全靠读者的卡开不了 —— 否则 `done` 退化成自评。
- 一条判据从 `{"读者":…}` 换成 `{"cmd":…}` 叫**毕业**,可数。

判官报告 `reports/xxx.json`:

```json
{"judge":"改动审阅人","answers":{
  "x1":{"答":"找到","引文":"<证据里的一小段,逐字>","证据":"<我看过的东西,原样>"}}}
```

上面那条 x1 的「过」是 `没找到`,所以这里的「答」只能从 `找到` / `没找到` / `答不了` 里挑。
答 `没找到` 的那一份长得不一样:不给 `引文` 和 `证据`,给 `搜了什么`。
**这份范例也被 `python3 tools/doc_cards.py` 拿去核** —— 它跟上面那条判据对不上就红,
因为真漂过一次:判据的「过」改了,这份范例的「答」原封没动。

### 判据包

一组命名 + 带版本的判据,**按活的类型切**,放在 `packs/`。卡按 `pack@version` 引进来:

```json
{"id":"…","题面":"…","引":["<包名>@<版本>"],"accept":[ …本卡自己的… ]}
```

**这里不写具体有哪几包、哪个版本** —— 去看 `packs/` 和卡文件本身。
手抄一份包名和版本必漂,这件事实测过不止一次 ——
**连上面这句警告自己都漂过**:它原来举了具体版本号当例子,而那个号后来又变了好几轮。

`spec_hash` 算的是**展开之后**那一份 —— 包的内容一改而版本没升,判的时候当场对不上。
**包只能靠升版本演进,改不动老卡。**

判决**逐条出,不合成总分**。一条不过,整卡不过。verdict 里出现 `score` / `总分` / `percent` 一律拒收。
改判据?**允许,但要留疤**:走 `amend`,写清为什么,**这张卡此前的 verdict 当场全部作废**。
那一笔还会记下**动的是哪几条**(加了哪几条 · 删了哪几条 · 改了哪几条)——
只记一个整卡的哈希的话,「补了一条」和「把唯一那条硬的改松了」在账上完全同形。

> `cards/archive/C-1.json` 是历史:它在 `b686dee` 上按当时的判据形态判过 PASSED,**不追溯改**。

## 七条规矩

**这张表不在这儿 —— 跑一次 `make check`,它打出来的七行就是。**
README 手抄一份规矩表,上一轮实测漂了(表里写「至少一条 auto」,盘上早已是
「至少一条判据由命令来答」)。**一份没有对账者的抄件必然烂**,所以这里只留 id:
`R1` 账只能追加 · `R2` · `R3` · `R4` · `R5` · `R6` · `R7`,正文去 `make check` 读。

每条同时有**执行器 · 必红用例 · 绿对照**,三样缺一这条规矩不存在。上限七条 —— **要加一条,先砍一条**。

**R7 是自指的那条**:把任一执行器换成恒真,它的必红用例就该不红了 —— 不红则 `make check` 判红。

`make check` 在七行下面还打几行**不计数**的。它们左右不了一件活算不算完成,所以不占规矩位;
但会报错的例子一个都不能少。有哪几行去屏幕上读,这儿不抄。

其中最新那行叫**重话**,管的不是「对不对」,是「有几份」:

```bash
python3 tools/saidtwice.py            # 跨文件一模一样的长句子,有没有哪处没人认领
```

一句话在仓里存了四份,答案值变了之后一轮只改掉两份 —— 剩下两份每一份单独读都通顺,
而没有任何东西发现。所以两个方向都红:冒出一处没认领的(你又抄了一份,写一句为什么),
或者认下的那一处对不上了(**两份里你只改了一份**)。

## `pattern/` —— 系统的记忆

一个跨行业的共享库:一群 agent 各自把遇到的具体事件写进去,并**猜**它背后是什么规律;
别人后来遇到自己的事,判断「我这个也属于那条猜测」就挂上去。
**一条猜测底下互不相识的事件越多,越可信** —— 不是谁认证的,是被互不相识的经历撑起来的。

设计上它和验收是同一件东西的**软硬两面**:判完之后把这一轮的经历写回库里(软),
而库里一条被反复撞上的猜测凝固成判据包里的一条(硬)。
**这是意图,不是当下的实情** —— 软的那一面走通过,硬的那一面一次都还没发生。
两头各是多少,`python3 tools/reflectland.py` 印出来,**不在这儿抄一份**:
沉淀那一步落的是「要不要写」这个决定,落地是后来在库那一侧发生的,
**说要写和真写了在账上完全同形**,这个数就是为了把两头对上。

**开卡前先查它**(见上面那条 `--查库`)。查了什么、查到没有、用上没有,都落进账里 ——
于是「这个库到底有没有被用上」是一个**数得出来**的东西,不是一种感觉:
`python3 tools/lookupstat.py` —— 它按开卡那道门认的那两栏分类:查过的几张、其中真用上的几张、
明说没查的几张、这一栏根本没记的几张。**最后那个数是老账留下的**,那时还没有这一栏。

**改得动,但要过一次纯模型评审。** 库原来只有「写进去」这条路 ——
第一次真用它,审阅人就逐条指出措辞没翻干净,而没有任何通道可以改。现在有了:

```bash
python3 tools/correct.py --提案 <订正.json>          # 自己发起评审
python3 tools/correct.py --提案 <订正.json> --评审 <评审.json>   # 或把评审记录交进来
```

订正一条要写清:`{节点, 栏, 改前, 改后, 为什么}`。**「改前」必须跟库里现在的值逐字一致** ——
对不上就说明你手上那份是旧的,当场拒。

评审是**一次纯模型调用,不是 agent**:工具全摘掉(`--tools ""`,一张空白的准入名单 ——
不是一张要手抄的黑名单,黑名单会随对方加工具静默漏),它看不到仓库、翻不了别处,
只对着「改前 / 改后 / 为什么」答三问 —— 还是在说同一件事吗 · 是不是只改了措辞或事实
(没有加强或削弱这条主张)· 有没有把一条具体的事实换成一句更空的话。
**三条全合格才许写**,提案与评审一起追加进 `pattern/docs/corrections.jsonl`。

「工具真摘干净了没有」不是读文档读来的,是当场验的:
`python3 tools/toolsoff.py` —— 往盘上放一行口令叫它读,摘掉工具那次读不到、
不摘那次读得到。**后面那次是对照**:没有它,「摘干净了」和「它这次压根没打算读」同形。
要联网,所以不在 `make check` 里。

实测:把「376 件(94.2%)」改成「绝大多数」被当场拒,理由是「削弱了原文的事实支撑力」。
