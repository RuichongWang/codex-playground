跨行业假说库

一群 agent 边干活边把经历写进共享库、互相猜彼此的假说——三轮建库跑通了，「库能不能让判断变好」还没测到，而上一轮实验的设计本身就测不出来。

90 条材料 · 310 个假说 · 1396 条 link 累计约 $237 分支 claude/pattern-hierarchy-experiment

三个命题的状态

已验证 互不相识的 agent 会独立归到同一个猜测下面。第二轮 30 个提议 agent 打第一轮冻结的库，283 条正 link 里 217 条（77%）落在上一轮完全另一批人建的 pattern 上。
已验证 抽象能跨类型接住。第三轮换成教科书原理和「做对了」的案例，71% 仍落在前两轮从事故里长出来的假说下面；负 link 密度翻了近三倍。
未测出 库能不能让判断变好。迁移实验是 null，但天花板效应和检索失效都能产生同样的 null，含义相反。这一轮没有分辨力。

库建起来了

三轮各 30 条材料，每轮打上一轮冻结的库。写入 agent 互相不可见、只看只读快照，所以「撞上同一个假说」是独立发生的，不是被撮合的。

事故 → 假说

医疗运营、供应链、电力、制造召回、软件事故、交通教育。最强的假说 P43 现在有 65 个独立事件、48 个来源、2 条反驳。

另一批人、另一批事件

金融风控、农业水资源、建筑基建、公卫、赛事。还专门造了配对语料测「同情境自报」——这个机制轮 1 一次都没触发过。结果：同一起事故的两个视角判对了；两起机制雷同的不同事故正确地没有合并，而是共同 link 到 4 个相同的假说；表面用词相近的干扰项没有误判。

通识与「做对了」的案例

教科书原理 20 条 + 有边界条件的最佳实践 5 条 + 本来会出事但没出事的案例 5 条。后者直接对治「只看事故就分不清机制危险还是机制常见」这个认识论缺陷——采集时找到了同机制对照：福岛第二对福岛第一、爱信火灾对一般 JIT 单点失效。

库反过来限定了教科书：Goodhart ⊣ P61——「反例（针对流行转述的过宽读法）：P61 明确把预演天数当成日程压力下的考核目标，却没有出现 Goodhart 式失效，且被 8 个独立事件支持。原因是这个量没有旁路。」

教科书给库补边界，库给教科书补反例。这个方向是原设计里没预料到的。

迁移实验：null，而且这个 null 不能当结论

30 个 held-out 案例，来自六个被永久锁定、以后扩库必须避开的领域（采矿、航天、司法监狱、影视档案、渔业极地、国防采办）。污染探针分层干净：认得出 15 / 认不出 15，达到预注册门槛。

两个解释都还站着，含义相反

天花板。裸模型预测准确率已经 0.933、条件 F1 已经 0.845，没余量可涨。题面虽不泄露答案，但仍含足够判据；而条件清单是同族模型从同一份源材料写的，所以另一个模型读题面就能收敛到 82%——这个指标测的是读题仔细程度，不是可迁移的抽象。

检索失效。抽查 C 拿到的库内容，相关性跟 D 的张冠李戴差不多。给「监测型干预的前提」那道题检索到的是「外部二值放行事件」「优化器排紧的计划网络」——一条对不上。那这次测的是「不相关的库 vs 不相关的库」。

最讽刺的是：这个项目一开始的命题就是「层级下钻 > 平铺 top-k」，而我在收官实验里用的正是平铺字面 top-k。

两个差点变成结论的错误

不等长的臂之间比了均值

首轮报表在各臂各自的有效子集上取 Brier 均值。C 有 3 个案例没吐出概率（恰好都是难题），均值从 0.064 掉到 0.014——看起来像「库让判断质量提升 5 倍」。在四臂共同子集上重算，四个臂是 0.013~0.017，毫无差别。已修：报表强制用交集。

把自己的 KeyError 报成了模型的问题

我曾报告「长上下文降低格式遵从率」。真实原因是库里 189 条 prescription 中有 1 条的 solution 指向不存在的节点，被 8 个案例检索到，打掉了 120 次运行里的 8 次。库块只有约 3.4k token，对 1M 窗口根本不叫长。已修：删掉那条、格式化器加防御、拼装器加校验。

已经改掉的：库从「材料」变成「环境」

之前是静态检索 top-8 塞进 prompt。现在四个 arm 拿到完全一样的工具——Bash、CLI 和一个配套 skill——差别只在指向哪个库、检索准不准。

  • Skill 教的是怎么走库，不是命令表：别指望一次 search 命中（别人用的是他自己行业的词）；catalog | grep 跨行业时比 search 好使；找到一条像的立刻看 neighbors；一定要看反驳，它直接给出边界；拿到解法先查条件；库里没有就说没有。
  • 安慰剂重新设计：喂错内容在 agent 能自己查之后就不可比了（它会重查一遍）。新的 D 是盲检索——同一个全库、同样的工具、同样的工作量，但 search 返回与查询无关的真节点。它分离的是「有库可查」和「查得准」。
  • 提示走 stdin：argv 单参数上限 128KB，中文一字 3 字节，这个坑踩了两次。已从根上消掉。
  • 轨迹全量落盘：之前只存最终答案和轮次，中间做了什么是黑盒。

第一次 agentic 运行：跨域迁移真的发生了

16 轮、225 秒、$1.33。它在推理里直接引用了库里的节点：

这正是 I36 的形状：剂数在总量上「到货正常」，而最优先段可用量为零。

I36 是日本 2021 年注射器死腔与瓶剂量不匹配（1.44 亿剂按 6 剂/瓶签约，普通注射器只能抽 5 剂，凭空少 1200 万人份）。它把这个搬到了加州影视退税扩容上——判定 failed、概率 20，全对。

一个越界行为要记一笔

第 9 步它去 grep 了 /root/.claude/projects/…/tool-results——那是我自己的 session 记录目录，不是库。只读、无害，但说明 --add-dir 之外它仍能访问 home，评测环境的隔离不够干净。要在下一轮收紧。

下一步

  • 把 skill 的教法推广到写入侧。轨迹显示读取侧的六条教法全部生效（见上），但写入 agent 用的还是硬编在 prompt 里的规则。同一套「怎么走库」应该合并成一份。
  • 把题出难。不给干预、让 agent 自己提，再跟实际奏效的做法比；条件清单必须包含从题面推不出来的条目；题面再削一层；把成败配比压到 0.5 附近。30 个案例的 ground truth 和污染标注都能复用。
  • agentic 全量。单次约 $1.33 × 120 次 ≈ $160，比静态版贵一个量级。建议先看轨迹、改完 skill 再跑。

要你定的三件事

  1. 先修题还是先修检索？两个 null 解释我建议先修题——因为即使检索完美，天花板还在那儿，实验照样没有分辨力。但你如果更想先看「库到底能不能被查到」，那就先跑 agentic 全量。
  2. $160 花不花？agentic 单次 $1.33，比静态版贵十倍。可以只跑 C 和 D 两臂（省一半），或者先跑 10 个案例探路。
  3. 要不要引入第二个模型？现在建库、答题、判分全是 opus-5 —— 条件清单和答案同源，是天花板效应的一个成因。换个模型判分或答题能拆开这层同源性，但会引入模型能力差异这个新变量。
