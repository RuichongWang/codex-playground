# 用途普查：这个库能干什么（2026-09-05）

## 这一轮在做什么

前三轮一直在问同一个问题：「agent 用了库，答案是不是更好」。四个指标、三次改题，**全部撞天花板**。
这一轮换了个问法：**先不管怎么测，先问这个库到底能干什么** —— 六路 subagent 并行发散
（互相不可见，各走一条道），回来再筛。允许改造库本身。

六路的角度：
1. 从数据结构出发（这个图能支持什么 query）
2. 从人和钱出发（谁会用、谁会付钱）
3. 从 AI 能力短板出发（当前 agent 系统性做不好什么）
4. 从改造库出发（加什么维度能解锁什么）
5. 怪用法（故意找边缘、反直觉的）
6. 科学命题（什么主张只有我们能证）

另有一路在此之前跑的：失效模式类任务的公开评测现状。

共产出约 110 个想法。下面是筛选结果和筛选依据。

## 一、先说一个改变判断的实测结果：库的三层增长速度完全不同

对三个冻结快照（30 / 60 / 90 事件）拟合 Heaps 指数（β=1 为线性增长、不饱和；β 越小越饱和）：

| 层 | 30 / 60 / 90 | β | 读法 |
|---|---|---|---|
| **负 link（否证）** | 83 / 160 / 241 | **0.97** | 几乎完全线性，**完全没饱和** |
| **condition（条件）** | 68 / 114 / 177 | **0.86** | 基本没饱和 |
| pattern（抽象） | 161 / 234 / 310 | 0.59 | 在饱和 |
| order-2（高阶抽象） | 38 / 43 / 63 | **0.43** | 饱和得最快 |

**推论：我们四次撞天花板，可能是因为一直在用饱和的指标测饱和的那一层。**
rubric 打的是「答案写得好不好」，吃的是 pattern 和高阶抽象 —— 恰好是 β 最小的两层。
而库里增长最快、最不饱和的是**否证和条件**，从来没被测过。

**这也是那笔 $350–450 斜率实验的免费预演**：按现在的设计（主指标绑在 β=0.43 的那层上），
斜率大概率是平的。

（算法：`math` 三点 log-log 拟合，数据来自 `runs/r2/library_round1_frozen.json`、
`runs/r3/library_round2_frozen.json`、`runs/r3/library.json`。）

## 二、库的其它实测结构事实（本轮新算，此前从未看过）

| 量 | 值 |
|---|---|
| condition 从来没被任何 link 碰过 | **151 / 177** |
| prescription 只有 ≤1 条 evidence | **187 / 188**（其中 **61 条是 0**） |
| pattern 只有 ≤1 条直接 item 支撑 | **158 / 310** |
| `novel=False`（同情境自报） | **28 / 1396** |
| 负 link 的靶子 | 81 个，**top6 吃掉 80/241** |
| item 的真实结局标签（库节点上） | worked 57 / failed 13 / unknown 20 |
| 153 个可能的域对里已被某条 pattern 跨过 | **150** |
| 独立 source 数 | 55 |

两条直接结论：

- **「域之间没有边」这个洞不存在**（150/153 已覆盖）。别再往那个方向找缺口。
- **洞在条件和证据侧**：`condition.test` 是全库唯一能被**客观判对错**的东西，
  一等公民、有可执行判据，然后 151/177 从没被印证过一次 —— schema 给了它地位，写入流程没给。

### 一个必须修的内部矛盾

`store.py` 的 `score = events*3 + sources*2 - refutes*2`，
但 `SKILL.md` 第 85 行写着「**反驳不等于它错了，等于它有边界**」。两边直接打架。
而且按 β 看，**被扣分的那一层（负 link, β=0.97）正是增长最快、最独有、
公开事故库里根本没有的那层资产**。

## 三、六路里的三处独立收敛

六路互相不可见，却撞到同一批结论上 —— 这正是这个库自己的认识论（独立收敛 = 可信度）：

**① 库该当否决器，不该当答题者**（4/6 路独立提出）
结构路「库当评审员」、怪用法路「241 条负 link 当攻城锤」、能力短板路「否证任务 / 误用率」、
商业路「这个库不该卖案例检索，该卖否证」。
共同理由：四个撞天花板的指标**全在生成侧**；而库的形状（241 条反驳、177 条判据）
本来就是用来**否决**方案的。换成成对判别，基线 50%，天花板结构性消失，
且它吃的正是 β=0.97 那一层 —— 反例越多能否决的越多。

**② 条件层是被浪费的核心资产**（4/6 路）
151/177 从未被印证；β=0.86 不饱和；
`condition.test` 是唯一能挡住「**航空跟医疗不一样**」这句拒绝的东西 ——
它把跨行业类比从励志故事变成可否证断言。这句拒绝在文献里有正式版本，
是所有跨域安全教训迁移的死穴。

**③ 独立性可能是虚的，得先查**（3/6 路）
`CLAUDE.md` 写着独立性是可信度的**唯一**来源，但 1396 条 link 里 `novel=False` 只有 28 条。
外部实测这类「相关痕迹被当独立来源」的自然发生率是 0.597
（[GovMem 2607.02579](https://arxiv.org/abs/2607.02579)，人工复核 133 条外部候选**一条都不该自动晋升**）。
**必须先查 —— 不是因为它好，是因为它可能让「跨轮复用 77%」「跨类型 71%」全部要重算。**

## 四、应用场景筛选

**筛选用的那把刀**：裸模型 + 一份原始语料 grep 能不能做到？能，就出局 ——
那不是这个库的价值，是语料的价值。活下来的只有需要**结构**的：
负 link、condition 的 `test`、多来源独立收敛。

110 个想法里过刀的不到 15 个。

### 第一梯队：库不可替代，且现在就能做（不需要新语料）

**1. 否证器 / 坏 pattern 试纸**
库已自动长出四条「零正证据、10–16 条独立反驳」的流行谬误 —— 没人要求它这么做：

| pattern | 内容 | 正 | 负 | 反驳来自 |
|---|---|---|---|---|
| P13 | 大型系统上线事故的根因主要是软件技术缺陷，加强选型与测试即可预防 | **0** | 14 | 13 个 agent / 14 个 item |
| P14 | 对失败的大型变革项目，换高管问责本身足以扭转结果 | **0** | 15 | 13 个 agent / 15 个 item |
| P28 | 面对突发流量，加机器/autoscaling 是主解法 | **0** | 10 | 10 个 agent / 10 个 item |
| P40 | 事后成立独立调查委员会、公开道歉认领责任 | 3 | 16 | — |

反驳都是具体的，且出现了跨域否证：

> P28 ⊣「我们在 14 分钟内试图加 1200 台机器，结果扩容动作撞上 fd/配额上限并把更多流量灌进已饱和的网关」
> P28 ⊣「**不加一张床、不加一间手术室、不加人，只重排日程**，等待时间降 28%/34% 且吞吐反涨 24%/37%」

第二条是**医院的案例反驳了一条软件领域的常识** —— 这是 end goal 那句话的实例，
只不过发生在**否证**方向，不是我们一直在测的「生成更好答案」方向。

- **不可替代性**：CSB / NTSB / MAUDE / ASRS / NSPCC —— 全世界的事故库都只记**发生了什么**，
  **没有一个记「我打算做的这个动作，别人做过没有、成没成」**。我们有 57/13 的干预结果标注和 241 条带理由的反驳。
- **需求有硬数字**：香港公立医院 RCA 的 760 条建议里 **82% 是弱建议**（培训教育占 61%），
  强建议只有 2%，同类事件在 RCA 之后照样重复
  （[PMC7275338](https://www.ncbi.nlm.nih.gov/pmc/articles/PMC7275338/)）。
  2017 年那篇 RCA 批评列的八条无效原因里有一条就是
  **failure to aggregate data across institutions**（[PubMed 27940638](https://pubmed.ncbi.nlm.nih.gov/27940638/)）。
- **有第三方裁判**：IHI 的 **RCA² 动作强度量表**，独立于我们，baseline 公开
  （[IHI RCA²](https://www.ihi.org/library/tools/rca2-improving-root-cause-analyses-and-actions-prevent-harm)）。

**2. 三态体检：「你现在踩在哪几条 condition 上」**
跑 177 个 `test`，输出 满足 / 不满足 / **查不到**。第三态是关键 ——
「你连自己踩没踩都不知道」是市面上 KRI/tripwire 方法论**结构上给不出**的输出（它们都是人工设阈值）。
前置工作：151/177 从没被印证过，得先筛掉伪 test（「判断文化是否开放」这种）——
让三个独立 agent 只看 test 去执行，一致率低的就是伪的。**这个筛选不需要任何外部数据。**

**3. 盲区探测（negative space）**
给一个组织的全套 SOP/runbook，报**它一条都没提到的**高阶跨域 pattern。
答案是补集不是检索结果 —— **这是 grep 结构上做不到的**。
可合成验证：从完整 runbook 人为删掉一节，看能否点出被删的那节。

### 第二梯队：值钱，但要么需要新语料、要么验证滞后

| 场景 | 为什么值 | 卡在哪 |
|---|---|---|
| **临床试验方案设计** | ground truth 最硬 —— 修订发不发生、几次、**$535k/次有发票**；76% 的试验碰到方案修订、45% 判定可避免，而可避免的主因是**运营可行性**不是医学（招募≈供应链、依从性≈流程遵从） | 要新语料 |
| **PE 运营尽调** | 付费意愿最高、决策链最短；他们现在在为**更差的替代品**付钱（专家网络 $1000+/通话，31% 专家自认不够格）。专家网络卖的是**同行业**共识，而共识恰好是把整个行业一起埋掉的东西 | ground truth 滞后 2–3 年，且不公开 |
| **再保险 emerging risk** | 有可比公司做锚（Praedicat 被 Moody's 收购）；我们补的是它够不着的一半：它挖科学文献（这个物质有毒），我们挖运营失效（这类安排在四个行业都塌了）。累积责任恰恰产生于跨行业共同结构 | **需要给 item 加日期**才能 backtest |
| **器械使用错误预测** | MAUDE + 召回库是真 held-out，能严格切时间；MAUDE 里人因/使用错误没有检索维度、字段常缺，而报警疲劳/模式混淆/默认值陷阱在航空驾驶舱、工控 HMI、金融终端都有实例，MAUDE 一条都没有 | 要新语料 |

### 明确砍掉

| 砍 | 理由 |
|---|---|
| 安全漏洞挖掘（CVE/代码） | 判分 oracle 不兼容（那条线全靠 crash 触发等确定性 oracle）；代码漏洞是**另一个抽象层**不是另一个领域；三组措辞搜「跨域历史事故抽象→找漏洞」**零命中** |
| **SRE 事故复盘（作为验证场景）** | 演示价值最高、证据价值接近零 —— 软件运维正是模型权重装得最满的域，会精确重演我们那个 null。且赛道拥挤 |
| **跨行业案例搜索引擎** | 所有人都说想要，没人为检索付钱。90 个 item 打不过 140 万份免费的 ASRS。付钱的是**否证**和**推送**，不是检索 |
| 公共卫生应急 / 新任高管 | 瓶颈在**执行与政治**不在知识 —— 2020 前每一份大流行推演都写对了，没人照做 |
| 人类失败周期表 / 组织改口检测 | 前者不产生可证伪预测（「落不进格子」和「格子太粗」事后分不开）；后者 n 太小，换公关团队会完整伪装成「学习」 |
| 假报告生成 | 只当空话计的对抗测试集，一次性用完即弃，不做产品 |

## 五、本轮决定

**从第二梯队入手，首选「临床试验方案修订预测」。**

理由（比「方便测试」更硬的那条）：**ground truth 不是我们写的**。
我们撞天花板最深的一个根因是 —— held-out 的条件清单是**同族模型从同一份源材料写出来的**，
所以那个指标测的其实是「读题够不够仔细」。
而「这个方案后来改没改、改了几次」是**世界写的**，我们碰不到。

外加两条：它天然是**带日期的预测任务**（写得好看没用），
且日期让污染可以分层检验。

### ⚠️ 必须处理的重叠

临床试验和医疗器械**跟库里的 `healthcare` / `publichealth` 域重叠**。
不处理的话测出来的是**知识冗余度**不是**迁移增益** —— 正好撞上 `CLAUDE.md` 写着的那个陷阱。

**处理办法**：跑的时候 `--mask healthcare,publichealth`，
让库只能用**别的 16 个域**长出来的抽象去打医疗题。
这也是域标签 + 运行时 mask 那套机制第一次真正派上用场。

### 下一步（按顺序）

1. **半小时的数据可行性核查**：ClinicalTrials.gov 的版本历史能不能拿到
   「原始方案 + 修订了哪一节 + 什么时候」。拿不到就换 MAUDE。
2. 定题面与判分，**写预注册**（硬规矩 4：先写再跑，不许拿旧结果当改题理由）。
3. 跑之前先做第六节那几件零成本的离线自查。

## 六、零成本、纯离线、不碰任何硬规矩的自查（建议先做）

1. ~~三层 β~~ ✅ 本文第一节
2. **competence 体检**：把每条 pattern 分成 pivotal（唯一支撑某些 item）/ auxiliary（被别人完全包含）。
   **不做这个，斜率跑出来读不懂** —— 平到底是「库无用」还是「新增全是重复」，只有这个能分开。
3. **留一法自检**：遮掉一条 item 的全部 link，把它的 `what` 当查询，看库能否推荐回被遮掉的 pattern。
   这是一个**不需要被试模型、不吃天花板**的库质量指标，三个快照都能跑。
   ⚠️ 只能当辅助诊断；一旦拿它当主指标报结果就碰硬规矩 4。
4. **可刷倍率**：灌 3 个同事件多视角的假 item 进快照，量出 credibility 涨几倍。
   这个数决定后面所有「扩语料」提案安不安全。
5. **收敛度 ↔ 跨域引用广度**：已初算 corr(独立事件数, 被引题数)=0.27、corr(反驳数, 被引题数)=0.11，
   差分层与 CI。它直接回答「收敛率能不能当可信度代理」。

## 七、三条红线（提案，待确认后写进 CLAUDE.md）

1. **缺口清单绝不能回灌给提议 agent。** 破坏硬规矩 2，而且**是静默的**：
   `events` 照涨、复用率还会更好看，但「独立撞上」变成「被引导撞上」，
   事后没有任何办法分辨哪些印证是真独立的，只能全部重跑。
2. **绝不让任何模型改写 / 归纳 / 合成 claim、test、why —— 包括 triage「顺手把两条合并成一句更好的表述」。**
   破坏硬规矩 3。已核 `pk/assemble.py` 的 `verify()`：它逐字校验
   `claim` / `test` / `why` / `item.what` 四类字符串来自原始提议，
   这把「不许发明」从 prompt 变成了**物理约束**。一旦放宽，就再也没有机制能区分
   「agent 猜的」和「triage 编的」。
3. **绝不给库加一个自动目标函数去筛选 / 打分 / 退休写入内容。**
   破坏硬规矩 1。库会朝那个函数优化，而函数是我们写的 ——
   于是它最终印证的是我们的先验，不是外部结构。
   这看起来像「库变干净了」，实际是把一个**收敛于世界**的系统换成**收敛于自己**的系统。

**附带一条**：若以后要把 agent 真实任务轨迹灌进库，那是唯一一条能绕过人工审稿、
把六个保留域悄悄带进来的通道 —— **闸门必须写在代码里，不能写在 prompt 里**。

**商业化的隔离要求**：六个保留域里有很好的客户（尤其国防采办和采矿）。
**只要为了做生意去补这些域的语料，held-out 就永久失效且不可逆** ——
商业化和实验必须在语料层物理隔离，否则第一个客户就把实验杀了。

## 八、本轮顺带发现并已修正的账目错误

- **撤回「负 link 密度翻三倍」**（原挂在 `CLAUDE.md` 的「已经成立」清单里）。
  从三个冻结快照直接数，每轮新增负 link 是 83 / 77 / 81，即每 item **2.77 / 2.57 / 2.70，是平的**；
  只看 item→pattern 更是逐轮下降（2.63 / 2.53 / 2.20）。
  仍然成立的是**形态**（第 3 轮的负 link 专挑通识没写出来的适用边界），不是密度。
  详见 `docs/experiment-plan.md` 第 3 轮那节的更正块。commit `658d865`。
