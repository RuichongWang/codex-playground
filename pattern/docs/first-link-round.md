# 第一次挂接:把这几天的教训拿去库里查(2026-09-17)

**做法**:把 `done` 那一侧这几天真实撞出来的五条教训,写成机制层的说法,
再去 90 事件 / 310 条猜测的库里找有没有已经存在的能挂上去。不写代码,不改库。

**结果:五条里四条挂得上。** 而且其中三条,库给的判法比我们自己那条硬。

---

## 挂上了的四条

### 1. 「一个检查看起来在把关,实际上没有」→ 三条独立的猜测,三个不同角度

我们的事件:验收要求「引文必须是判官自己给的证据的逐字子串」。
它只管引文是不是抄来的,**不管引文跟问题有没有关系** —— 实测有人答「否」、
拿一段无关输出当证据,照样放行,而正确答案是「是」。

库里挂得上的三条:

- **P280**(解法侧)给了一个**可以真算一遍的判据**:同一个装置,「假如我是好的」和
  「假如我是坏的」各自要付的期望成本,比值是多少。**接近 1 就说明它不携带任何信息** ——
  「大多数流于形式的资质、承诺书、宣誓声明都死在这里」。
  → **这是我们自己没有的东西。** 我们那条只会说「这个检查是假的」,说不出「假到什么程度」。
- **P155**:清单沿「正向的、被设计出来的关系」枚举,而真正致害的来自反向关系;
  于是**所有清单驱动的检查都会返回阴性**。
- **P188**:赶工时最先被牺牲的是「分离」类控制,结果东西「功能完整、能演示、**能自检通过**」,
  而保证它正确的那套机制已经被拆掉了。

### 2. 「答『没有』结构上不可证」→ P286,同一个逻辑动作

P286 的末句几乎逐字同形:

> 「我正在压的这个量,是谁的原料?**答不出来,不等于没有,只等于那一项没人记账。**」

它来自一个完全不同的场景(压方差/压库存/压工期那类优化),而落点是同一个。

### 3. 「同一件事上混两种判者」→ P296,而且它多给了一条

P296 要求「把角色显式拆到不同的人身上 —— 维持现状/读流程/算方案/独立复核」,
并且**必须有一个人不执行任何动作、只做复核**。

→ 最后那半句我们没有。我们只做到了「判的手不是干的手」,没做到「有一只手什么都不干」。

### 4. 「手抄的东西必然跟实际对不上」→ P109 是邻居,不是同一条

P109 说的是:真正生效的契约不是文档里那份,而是散落各处、以历史取值凝固下来的假设。
我们那条说的是:**两份都写下来了,而其中一份会慢慢变假**。
同族,不同条。可以挂成邻居,不宜合并。

## 没挂上的一条

**「改验收条件时改了一栏,要重读全部四栏」** —— 库里找不到对应的。
可能它确实是新的,也可能它太窄(像是一条操作规程,不是一条关于世界的猜测)。
**先不往库里塞**,等它被第二次撞上再说。

## 一条必须写下来的方法缺陷

**这一轮的挂接是我自己拿关键词去 grep 的,而关键词是我按自己那五条想出来的。**
库自己的文档早就写过:它的检索是字面匹配,跨行业经常失灵,得换机制层的说法多查几次 ——
也就是说,**换一个不知道我们这五条的人来挂,结果可能完全不同**。

所以这一轮的四比一**不是一个可以拿去汇报的命中率**,它只证明一件事:
**库里确实存在能接住我们这类问题的抽象,而且比我们自己写的更硬。**

要拿到一个能信的数,下一轮得这么做:把五条事件交给一个**没看过我们结论**的判官,
让他自己去库里找,再跟这一轮比。
